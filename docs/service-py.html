services/core/service.py

Aurora Pay çekirdek servisinin transfer iş mantığı katmanıdır. HTTP katmanından (API) gelen istekleri alır, bellek içi depo (store) üzerinde hesap oluşturma, hesap sorgulama ve para transferi işlemlerini yürütür.

Bağımlılıklar

ModülKullanım amacı
storeBellek içi veri: accounts, transfers, idempotency sözlükleri.
feesfee_for(amount) ile transfer ücreti hesaplar (Decimal, ROUND_HALF_UP, 2 ondalık). Eşik 1000.00 dahil olmak üzere düşük oran (%0,25) uygulanır; altında %0,5.
reportsrecord_transfer(...) ile transferi sqlite transfer_log tablosuna yazar.
errorsAccountNotFound, AccountAlreadyExists, InsufficientFunds iş hatalarını tanımlar.
modelsAccountCreate ve TransferRequest Pydantic modelleri.

Modül düzeyindeki nesneler

  • logger – logging.getLogger("aurora.core"); print yerine kullanılır.
  • _lock – threading.Lock. "Kontrol et, sonra yaz" dizilerini (idempotency sorgusu, çift hesap kontrolü, bakiye kontrolü + borçlandırma) iş parçacıkları arasında atomik yapar.

Fonksiyonlar

get_account(account_id: str) -> dict

store.accounts içinden hesabı döner. Yoksa AccountNotFound fırlatır (API tarafında 404 ACCOUNT_NOT_FOUND). Kilit almaz; execute_transfer içinde zaten kilit altında çağrılır.

create_account(data: AccountCreate) -> dict

  1. Kilidi alır.
  2. data.id zaten varsa AccountAlreadyExists fırlatır (409 ACCOUNT_ALREADY_EXISTS).
  3. Modeli model_dump() ile sözlüğe çevirip store.accounts içine kaydeder ve döner.

execute_transfer(req: TransferRequest, idempotency_key: str | None = None) -> dict

Ana iş akışı. Tamamı _lock altında çalışır:

  1. Idempotency: anahtar verilmiş ve store.idempotency içinde varsa ilk yanıt aynen döner; yeni işlem yapılmaz.
  2. Doğrulama (yazmadan önce):
    • Kaynak ve hedef hesabı get_account ile bulur (yoksa AccountNotFound).
    • fee = fees.fee_for(req.amount), total = amount + fee.
    • Kaynak bakiye total'den küçükse InsufficientFunds (409 INSUFFICIENT_FUNDS).
  3. Transfer kaydı oluşturma: uuid4 id, tutar, ücret, para birimi, status="COMPLETED", UTC created_at.
  4. Raporlama: reports.record_transfer(transfer, src["owner_name"]) sqlite günlüğüne yazar.
  5. Yazma: kaynaktan amount + fee düşer, hedefe yalnızca amount eklenir (ücret hedefe geçmez), transfer store.transfers içine, varsa idempotency anahtarı altına kaydedilir.
  6. Loglama (kilit dışı): yalnızca transfer_id, from_account, to_account loglanır; PII yoktur.

Örnek akış

amount = 1000.00  → fee = 2.50  (eşik dahil, %0,25)
kaynak bakiye  : -1002.50
hedef bakiye   : +1000.00

Tasarım notları

  • Atomiklik: tüm doğrulamalar yazmadan önce yapılır; hata durumunda bakiyeler değişmez.
  • Eşzamanlılık: tek global kilit, aynı anahtarla gelen eşzamanlı isteklerin çift transfer üretmesini engeller.
  • Para tipi: tutarlar Decimal'dir; float kullanılmaz.
  • Hata zarfı: fırlatılan istisnalar API katmanında {"error": {"code", "message"}} biçimine çevrilir.
  • Dikkat: reports.record_transfer çağrısı bakiye yazımından önce yapıldığı için, sonraki adımlarda hata oluşursa günlükte kayıt kalabilir.
